Remove a project, agents that work without stopping to ask, and fixes for agents that did not start or could not reach Natamux. If you have v0.1.2, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Changes

- **Remove a project.** Choose **Remove project** in the menu of its group in the sidebar. Natamux forgets the repository; the folder, its branches and its tasks stay. See [Repositories](https://natamux.github.io/docs/guides/dashboard/#repositories).
- **Agents start in auto mode.** They do not stop to ask before each command. Set `"agents": { "permissionMode": "ask" }` in `.natamux.json` to get the prompts back. See [Auto mode](https://natamux.github.io/docs/agents/claude-code/#auto-mode).
- **Agents do not commit.** The Implement and Testing stages leave the changes uncommitted. Read them in the **Changes** tab and commit them there. A stage with `requireCommit` still asks its agent to commit. See [Checks](https://natamux.github.io/docs/concepts/stages/#checks).
- **"Start a task".** The **New workspace** dialog is now **Start a task**, and a repository is a "project" in the dashboard. The dialog shows the **Notes** field at once, so a task no longer starts with "(No notes.)".
- The task details panel starts closed. Open it from the title bar or a row.
- The terminal header shows the agent's icon and name, such as "Claude Code". A narrow pane shows only the icon.
- Removing a workspace works when its worktree folder was already deleted outside Natamux.
- **Fix: "command not found" when an agent starts.** Task shells start as login shells, so tools that `~/.zprofile` puts on the PATH are found. When the app cannot read the login shell PATH, it adds the Homebrew folders.
- **Fix: "proxy refused the connection".** Task terminals add `127.0.0.1`, `localhost` and `::1` to `NO_PROXY` and `no_proxy`, next to the hosts you already have, so agent hooks reach Natamux past a company proxy.

`SHA256SUMS.txt` lists the checksum of every file.

The Intel Mac and Linux builds are paused. The last release with them is [v0.1.2](https://github.com/lenhatthanh20/natamux/releases/tag/v0.1.2). On those systems **Check for Updates…** finds this version but no file for it, and shows an error. Keep using v0.1.2 there.

## Before you open it

This release is **not signed** with an Apple certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

An update from v0.1.2 does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
