Natamux stops a Review agent's `natamux done` from passing Implement after a send back, keeps more work safe across restarts and quits, and the website is new. If you have v0.1.2 or later, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Stages

- `natamux done` from a shell of a stage that does not run now is refused with a message. Before, a Review agent that sent a task back could pass Implement at once, and the two stages looped. See [What `natamux done` does](https://natamux.github.io/docs/concepts/stages/#what-natamux-done-does).
- A send back from a stage with **End the agent and close its shell when the stage is done** now also ends its agent and closes its shell. The next round starts a new agent. Shell 1 is never closed. See [End a stage's shell](https://natamux.github.io/docs/concepts/stages/#end-a-stages-shell).
- If your `.natamux.json` has an `agent-review` prompt that says "After send back, run `natamux done`", change it to "After send back, stop. Do not run `natamux done`."
- A task that waits for the tasks it depends on, or for its workspace, still starts after a daemon restart.
- When the agent runs `natamux done` while you click **Mark as done**, the checks run once, so a failure no longer uses up the agent's retry.
- A CI check of a task with no workspace or branch fails with a clear reason. Before, it could run in the daemon's own folder.
- Removing a workspace keeps the latest stage files, such as a spec written after a send back.

## Agents

- Copilot asks for input only when it shows a prompt, not on each tool call it approves by itself.
- A Cursor or Copilot hook file that also has a hook of your own is no longer replaced. See [Agents and hooks](https://natamux.github.io/docs/concepts/agents-and-hooks/).

## Terminal

- The notice of a task (needs input, review and the like) is in the workspace header row, so the shells no longer change size and blink when the task changes state. On a phone it stays under the header.
- A cursor the program hid stays hidden when a terminal opens again, so the second terminal no longer shows two cursors.
- Quitting the app or stopping the daemon waits for every shell to end, and stops programs that ignore the hang-up signal.

## Tasks

- A change that comes right after you edit a task file by hand no longer writes over your edit. The change is refused with `409 conflict`; try it again.
- A new task never gets the id of a task whose file was removed from outside Natamux.
- PR and issue links take only `http` and `https` URLs.

## Reliability and security

- The daemon checks its token by the route it runs, so a path with `\` or `..` can no longer skip the check.
- Calls to `gh` stop after 60 seconds, update downloads and checks have time limits, and quitting does not wait on a daemon that hangs.
- Natamux looks up pull requests once per project, not once per task, and a running agent no longer adds a log line every 30 seconds.
- Failed side work in a stage is logged, and the next stage still starts.

## Website

- A new [homepage](https://natamux.github.io/) that starts with a workflow, new pictures of the current dashboard in both themes, and a regrouped guide.
- The download section shows the unsigned app note as a callout.

## Before you open it

This release is **not signed** with an Apple or Windows certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

- **Windows:** run `Natamux-win-x64.exe`. If SmartScreen shows **Windows protected your PC**, click **More info**, then **Run anyway**. The installer needs no administrator rights.
- **Linux AppImage:** run `chmod +x Natamux-linux-x86_64.AppImage`, then start it. On Ubuntu 24.04 and later, if it does not start, add `--no-sandbox` or install the `.deb` instead.
- **Debian and Ubuntu:** run `sudo apt install ./Natamux-linux-amd64.deb`. The app is `natamux-desktop`.

An update from v0.1.2 or later does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
