An agent now reviews the work and sends it back to Implement by itself, a stage can wait for your CI, and the sidebar shows each shell of a task with a comet for its progress. If you have v0.1.2 or later, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Stages

- The default pipeline is Context, Spec, Plan, Test spec and Implement side by side, **Automated tests**, **Review** and Release. No step between Plan and Release waits for you unless an agent asks. Tasks on their way keep their stages, and a project with its own stages in `.natamux.json` keeps them. See [The default pipeline](https://natamux.github.io/docs/concepts/stages/#the-default-pipeline).
- **Review** is an agent stage in its own shell (Shell 5). It reads the spec and the changes, writes `review.md`, and when something must be fixed it sends the task back to Implement with the problems. It does that at most twice; then the task waits for you. See [Review by an agent](https://natamux.github.io/docs/concepts/stages/#review-by-an-agent).
- The review by a person is now called **Manual review**, and **Manual QA** is now **Manual testing**. Both are in the catalog, not in the default pipeline.
- **Automated tests** (the Testing stage before) now runs before the review.
- **Check on CI**: Implement and Automated tests have a checkbox on their stage card. When the agent is done, Natamux pushes the work to `natamux-ci/<branch>`, waits for your CI, and gives a failure back to the agent. Your workflows must run on a push to `natamux-ci/**`. See [Check a stage on CI](https://natamux.github.io/docs/concepts/stages/#check-a-stage-on-ci).
- A stage that runs beside Shell 1, or in its own shell, can use another agent and arguments, such as a cheaper model: **Agent** and **Arguments** in its stage settings. See [Choose a model](https://natamux.github.io/docs/concepts/stages/#choose-a-model).
- The Spec stage writes a **Code map** of the files and functions to change, so the next stages do not read the code again.
- A new workspace starts from the branch of your main checkout as its remote has it now, so a checkout you did not pull does not start a task from old code. See [Base branch](https://natamux.github.io/docs/concepts/workspaces/#base-branch).

## Dashboard

- Each shell of a task has its own row under the task: its state, its agent, its stage and what the agent does, or a terminal icon and the program for a plain shell. A chevron before the task folds the rows. See [Sidebar](https://natamux.github.io/docs/guides/dashboard/#sidebar).
- A comet on the second line of a task shows how far it is through its steps, in the color of the current stage, with sparks while it runs. The diff size is no longer on that line.
- The task icon spins while any of its agents works.

## Terminal

- An agent you start yourself in a shell, such as `agent` for Cursor or `codex`, shows in the pane header with its own name. When its hooks reach Natamux it also has its own state, and it does not change the task. See [Shells](https://natamux.github.io/docs/guides/terminal/#shells).
- Natamux runs at most 30 shells in all.

## Before you open it

This release is **not signed** with an Apple certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

An update from v0.1.2 or later does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
