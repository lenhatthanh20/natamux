The desktop app now shows what the updater does, in the status bar and in Settings, and timed update checks no longer open a dialog. **Remove finished workspaces** and **Delete all done tasks** now clean up workspaces with files that are not committed too. A new install opens on a three-step welcome, and the stage settings of a project are more compact. If you have v0.1.2 or later, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Desktop app

- The status bar shows what the updater does: **Checking for updates…** (for a check you asked for), **Downloading 1.0.6 · 42 MB**, **Restart to update** (a click restarts, and asks first about unsaved drafts), **Natamux 1.0.6 available** (opens the release page) or **Update failed** (a click checks again). Under 1024 px wide it shows only its icon.
- A timed check never opens a dialog. A ready update shows one message with **Restart Now** and **What's New**. A failed timed check shows nothing.
- A ready update is not checked or downloaded again: **Check for Updates…** shows its dialog again. **Check for Updates…** is off while a check or download runs.
- **Settings → General → Updates** has a **Version** row with what the updater did last, such as "Up to date · last checked 3m ago" or "1.0.6 is ready to install". Its **Check now…** button reads **Restart to Update** while an update is ready. See [Updates](https://natamux.github.io/docs/guides/desktop-app/#updates).

## Tasks

- In the desktop app, **Remove finished workspaces** and **Delete all done tasks** / **Delete all cancelled tasks** no longer skip a workspace with files that are not committed. The confirm names each such workspace with its number of files, and reads **Remove anyway** or **Delete anyway**: those files are lost. A workspace that gets such files after the confirm opens is still refused, and the result message lists it. The web dashboard and the CLI do not change. See [Sidebar](https://natamux.github.io/docs/guides/dashboard/#sidebar).

## Getting started

- In the desktop app, when there is no task, the main area shows **Welcome to Natamux** with three steps, in place of "No tasks yet": choose a project (**Choose folder…** adds it at once, **Type a path…** opens the projects dialog), sign in to your agents (the command of each agent with a copy button), and set up your workflow (**Open workflow settings**). The welcome goes away with the first task. See [Add a project](https://natamux.github.io/docs/getting-started/quick-start/#add-a-project).

## Project settings

- In the desktop app, on the **Stages** tab, the **Agent** and **Kind** selects and the number fields **Agent send backs** and **Pause idle agents after (min)** sit on the row of their label. The checkboxes of a stage form one tight group. The settings themselves do not change.

## Before you open it

This release is **not signed** with an Apple or Windows certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

- **Windows:** run `Natamux-win-x64.exe`. If SmartScreen shows **Windows protected your PC**, click **More info**, then **Run anyway**. The installer needs no administrator rights.
- **Linux AppImage:** run `chmod +x Natamux-linux-x86_64.AppImage`, then start it. If it does not start, start it with `--appimage-extract-and-run`, or install the `.deb` instead. The updater needs `curl`.
- **Debian and Ubuntu:** run `sudo apt install ./Natamux-linux-amd64.deb`. The app is `/opt/Natamux/natamux-app`.

An update from v0.1.2 or later does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
