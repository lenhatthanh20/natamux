This version adds Strict mode and makes Natamux safer by default: agents see only their own task, CI gets only committed work, and Natamux keeps fewer secrets on disk. If you have v0.1.2 or later, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Security

These changes apply to everyone, also without Strict mode.

- **Check on CI** sends the last commit plus your changes to tracked files only. Files git does not track yet are never sent; the stage card names them. Add a new file with `git add` if CI needs it. See [Stages](https://natamux.github.io/docs/concepts/stages/).
- An agent reaches only its own task and its direct subtasks through the API, the `natamux` command and the event stream. Its token stops working when the task is Done or Cancelled.
- When the permission mode is `ask`, an agent argument that turns off approvals (for example `--dangerously-skip-permissions` or `--yolo`) stops the start with the reason. Natamux never drops the word and starts anyway.
- Agent config is checked in each task's worktree. When it differs from what you approved, **Start agent** is refused with a **Review config** button that lists the changed files. A project that has an agent config file asks for one new approval after the update.
- Deleting a task removes all its files from the data folder. Logs mask tokens and passwords in URLs. Data files are readable only by you.
- New commands: `natamux security`, `natamux support-bundle` (a bug report file with no task text) and `natamux purge-data`.

See [Security and privacy](https://natamux.github.io/docs/help/security-and-privacy/).

## Strict mode

For work with strict security rules, turn on **Settings > Security > Strict mode**. The status bar then shows **Strict**.

- Agents start in their ask mode, and auto mode is not allowed.
- Agent config is approved per worktree and checked right before each start.
- **Check on CI** sends only the last commit by default, or a tree you approve, or nothing.
- Agents never push, and they need a grant to open a pull request.
- GitHub tokens and SSH agent variables are taken out of task terminals.
- Blocked actions and security changes go to an audit log.

Settings that Strict mode does not turn on, kept in `security.json`:

- `network`: limit Natamux's own git, `gh` and update traffic to the remotes and hosts you list, or to this machine only.
- `isolation`: on Linux, run each task's Claude Code under Landlock, so it can reach its own worktree but not the rest of your home folder or other tasks.
- `data`: delete finished tasks after a number of days, and cap log sizes.

See [Strict mode](https://natamux.github.io/docs/reference/configuration/#strict-mode-securityjson).

## Before you open it

This release is **not signed** with an Apple or Windows certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

- **Windows:** run `Natamux-win-x64.exe`. If SmartScreen shows **Windows protected your PC**, click **More info**, then **Run anyway**. The installer needs no administrator rights.
- **Linux AppImage:** run `chmod +x Natamux-linux-x86_64.AppImage`, then start it. If it does not start, start it with `--appimage-extract-and-run`, or install the `.deb` instead. The updater needs `curl`.
- **Debian and Ubuntu:** run `sudo apt install ./Natamux-linux-amd64.deb`. The app is `/opt/Natamux/natamux-app`.

An update from v0.1.2 or later does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
