Natamux uses much less CPU while its window is open, the agent can draft your commit messages, agents come back on their own after a restart, and agents no longer ask to trust the task folder. If you have v0.1.2 or later, the app updates itself to this version.

Guide: https://natamux.github.io/docs/

## Dashboard

- The app no longer keeps the CPU busy while agents work. In a window without focus, every spinner, ring and stripe stands still, and the text in the title bar turns grey. With the focus, the moving stripes and dashes cost much less to draw. In our tests, an open window with all agents idle used about 20% CPU before.
- The **Needs you** strip at the top of the sidebar is gone. A task that waits on you is already a card with its question. The **N need you** pill in the title bar still lists every task that waits, also tasks without a workspace. A folded row shows its subtasks that need you, failed or are blocked. See [Sidebar](https://natamux.github.io/docs/guides/dashboard/#sidebar).
- The second line of a task row shows its agent's icon, open or folded. Each project in the sidebar has a header band with its name and the number of workspaces. An agent shell whose state is not known shows a grey ring.

## Agents

- **Generate** in the commit box (`Mod+Shift+G`) asks the task's agent for a commit message. **Commit…** drafts one too when the box is empty. Nothing is committed for you. When the agent is missing, fails or takes over 60 seconds, you get a simple draft from the task title and the files. See [Commit](https://natamux.github.io/docs/guides/changes-and-history/#commit).
- Natamux marks each task's worktree as trusted for the agent it starts, so the agent does not ask. For Cursor CLI and Copilot CLI this writes a file outside the worktree. See [Folder trust](https://natamux.github.io/docs/concepts/agents-and-hooks/#folder-trust).
- When Natamux starts again, the agents of running and waiting tasks start again on their own. See [A shell after a daemon restart](https://natamux.github.io/docs/guides/terminal/#a-shell-after-a-daemon-restart).

## Stages

- A failed CI check shows one short line per failed run in the stage card, with a link, not the end of the log. The agent still gets the log.
- When CI fails on a testing stage, the task goes back to the stage before it that changes code, such as Implement, with the failed runs. After two send-backs, the next CI failure waits for you. See [Check a stage on CI](https://natamux.github.io/docs/concepts/stages/#check-a-stage-on-ci).

The Intel Mac and Linux builds are paused. The last release with them is [v0.1.2](https://github.com/lenhatthanh20/natamux/releases/tag/v0.1.2). On those systems **Check for Updates…** finds this version but no file for it, and shows an error. Keep using v0.1.2 there.

## Before you open it

This release is **not signed** with an Apple certificate.

- **macOS:** drag Natamux to Applications and open it once. macOS blocks it. Then open **System Settings → Privacy & Security** and click **Open Anyway**. If there is no such button, run:

  ```sh
  xattr -dr com.apple.quarantine /Applications/Natamux.app
  ```

An update from v0.1.2 or later does not need these steps.

See the [install guide](https://natamux.github.io/docs/getting-started/install/).
