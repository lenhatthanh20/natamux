Natamux is an open-source Agent Development Environment. Each coding task gets a git worktree, terminals and a workflow. You can see what the agents are doing and step in when a task needs a decision.

Start with one task. Then change the stages, checks and approvals to fit your project.

## Your first task

1. **Add a project.** Choose the folder of a git repository. Sign in to the agent you want to use.
2. **Start a task.** Enter a title and context, then choose a project and an agent. Natamux creates the worktree and opens its terminal.
3. **Follow the work.** The sidebar shows task state. **Progress** shows the stages, results and approval gates.
4. **Review the change.** Read the diff, commit, push and open a pull request.

The [quick start](/docs/getting-started/quick-start/) explains each step and what you should see.

## How the parts fit

| Part | What it holds |
| --- | --- |
| [Project](/docs/guides/project-settings/) | A git repository and its shared settings. |
| [Task](/docs/concepts/tasks/) | The change, context, state and agent runs. |
| [Workspace](/docs/concepts/workspaces/) | The task's worktree, branch and terminals. |
| [Workflow](/docs/guides/workflows/) | The stages, checks and approvals a task follows. |

The workflow is saved in `.natamux.json`. Commit it to share the same process with other people working on the project.

## Shape the workflow

A stage is one step of the work. It can start an agent, run a command or wait for you. Stages can run side by side. A condition can send a task down a different path.

Use **Project settings → Stages** to change the process. A review stage can send a task back with findings, so the implementation agent gets a concrete next step.

- [Build a workflow](/docs/guides/workflows/) for complete examples.
- [Stages and gates](/docs/concepts/stages/) for checks, conditions and approvals.
- [The review loop](/docs/concepts/review-loop/) for agents that check each other's work.
- [Mix agents](/docs/guides/mix-agents/) to choose an agent and model for each stage.

## Keep the change in view

The task keeps its terminal, files, diff and branch together. Open a file in the editor, inspect changes side by side, or send a line comment back to the agent.

See [Terminal](/docs/guides/terminal/), [Changes and history](/docs/guides/changes-and-history/) and [GitHub](/docs/guides/github/).

## Bring your agents

Use Claude Code, Codex, Gemini CLI, GitHub Copilot CLI or Cursor. Natamux adds hooks to their sessions so state comes from agent events. Other terminal agents work through the terminal bell and `natamux ask` / `natamux done`.

See [Agents](/docs/agents/) and [Agents and hooks](/docs/concepts/agents-and-hooks/).

## Local data, familiar tools

Natamux keeps task data on your machine. Tasks are Markdown files; a SQLite index is a cache. The local daemon owns task state and the desktop app connects to it. You can also use the daemon through the CLI or a browser dashboard.

Your agents keep their own service logins. Git and GitHub operations use your own `git` and `gh`. See [Security and privacy](/docs/help/security-and-privacy/).
